# AGENTS.md

**Eäsis** — a Quenya self-study app (Kotlin Multiplatform + Compose Multiplatform). Read
[README.md](README.md) first for what's built and verified, [BACKLOG.md](BACKLOG.md) for
prioritized open work, [SPEC.md](SPEC.md) for the full design.

## Build and test

Always use the committed wrapper (`./gradlew ...`), never a bare `gradle` — see README.md's
"Run the logic tests" and "Build the Android app" sections for the exact commands.

## Generated data

Everything under `composeApp/.../composeResources/files/*.json` (lexicon, forms, phrases, lesson
text, lesson order) is generated by `tools/build_data.py` from Eldamo's data, not hand-authored.
Change `tools/skeleton.json` or the script and regenerate — never hand-edit the JSON.

## Commits and pushes

Never commit or push on your own judgment, for any code. Ask right before running `git commit`,
every time, and wait for an explicit yes — a passing build (`./gradlew :core:jvmTest`,
`:androidApp:assembleDebug`, `:composeApp:compileKotlinIosSimulatorArm64`, as applicable) is
necessary but never sufficient; it proves the code compiles, not that the user has seen it. Don't
assume general or standing approval: a "yes" covers only what the user has actually seen at that
moment, so if anything changed since they last signed off — a fix, a tweak, a rebuild — summarize
what's different and ask again before committing.

Commit messages are the user's own words alone — no `Co-Authored-By`, "Generated with", or similar
AI self-attribution trailer. A `commit-msg` hook enforces this; if a commit is rejected, strip the
trailer and recommit rather than bypassing the hook. One-time setup per clone:
`git config core.hooksPath .githooks`.
